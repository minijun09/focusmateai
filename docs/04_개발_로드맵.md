# 04. 개발 로드맵

## 1. 진행 원칙

현재는 기본 기획 단계이며 이 문서에는 향후 개발 계획만 작성한다. 일정은 확정하지 않고 각 단계의 산출물과 통과 기준을 중심으로 관리한다. 대상 기기, 인력, 예산을 확인한 뒤 기간을 산정한다.

MVP는 목표 입력 → 계획 확정 → 집중·휴식 → 기록·회고 → 코칭 → 다음 계획의 한 흐름을 끝까지 사용할 수 있는 수준으로 정의한다. 기본 보상과 일별·주별 통계를 포함한다.

## 2. 단계별 계획

| 단계 | 목적 | 주요 작업 | 산출물 | 다음 단계 통과 기준 |
| --- | --- | --- | --- | --- |
| 0. 기본 기획 | 문제와 범위 정렬 | 문제 정의, 5대 기능, 에이전트 구조, 개인정보·알림 원칙 정리 | 현재 README와 기획 문서 5개 | 문서 간 범위와 원칙이 일치함 |
| 1. 사용자·경험 검증 | 실제 불편과 최소 흐름 확인 | 고등학생 인터뷰, 화면 흐름 시안, 입력 부담·알림 선호 확인 | 검증 가설 결과, 화면 시안, 우선순위와 지표 기준안 | 목표 입력부터 회고까지 학생이 흐름을 이해하고 주요 불편이 정리됨 |
| 2. 기본 학습 흐름 구현 | AI 없이도 사용할 수 있는 기반 확보 | 계정 없는 저장, 수동·규칙 기반 계획, 집중·휴식 타이머, 결과 기록, 열람·삭제 설정 | 내부 검증용 기본 버전 | 핵심 흐름 사용 가능, 중단·복원·중복 저장·삭제 동작 확인 |
| 3. AI 코칭 통합 | 기록 기반 개인화 제안 검증 | 외부 전송 동의, 최소 요약, AI 제안 검증, 수락·수정·거절, 실패 시 기본 안내 | AI 코칭 포함 버전, 예시 시나리오 평가 결과 | 승인 없는 변경 없음, 잘못된 응답 차단, 미동의·연결 실패에도 핵심 흐름 유지 |
| 4. 보상·통계·알림 완성 | 반복 사용과 회고 지원 | 비금전적 배지, 일별·주별·과목별 통계, 선택적 알림, 보관 기간 자동 삭제 | 5대 기능이 연결된 MVP 후보 | 통계 정확성, 배지 중복 방지, 알림 제한, 원본·파생 기록 삭제 확인 |
| 5. 제한적 시범 운영 | 유용성과 부담 확인 | 자발적 참여, 동의 절차 확인, 핵심 지표 관찰, 인터뷰, 불편 수정 | 시범 운영 보고서와 개선 우선순위 | 중대한 기록 보호 문제 해결, 핵심 흐름 안정성·사용성 확인 후 확대 여부 결정 |

단계 2에서 데이터 보관 기간과 삭제 범위를 설계하고, 단계 4까지 자동 삭제를 완성한다. 실제 학생 기록을 사용하는 시범 운영 전에 전체 보호 절차가 작동해야 한다.

## 3. 기능별 MVP 경계

| 기능 | MVP에 포함 | 이후 검토 |
| --- | --- | --- |
| 집중 타이머 | 집중·휴식, 일시정지·중단·복원, 결과 기록 | 다양한 세션 구성과 접근성 개선 |
| 학습 계획 | 일일 계획, 가용 시간 검증, 학생 수정·확정 | 주간 계획과 일정 연동 |
| AI 학습 코치 | 최근 기록 요약, 짧은 제안, 승인 기반 조정 | 개인화 방식과 제안 품질 고도화 |
| 보상 시스템 | 시작·완료·재시도 배지, 표시 끄기 | 학생 피드백에 따른 성취 표현 확대 |
| 통계 | 일별·주별 시간, 과목별 시간, 완료율, 중단·재시작 | 장기 추세 분석과 선택적 내보내기 |

앱 자동 감시·강제 차단, 보호자 감시, 성적 예측, 경쟁 순위, 금전성 보상은 후속 개발의 확정 항목도 아니다. 필요성과 학생의 결정권을 별도로 검토한다.

## 4. 개발 착수 전 결정할 사항

- **플랫폼·기술 스택:** React + TypeScript + Vite 기반 반응형 웹으로 시작한다. 학생의 기기 환경과 백그라운드 타이머 동작은 구현·검증 단계에서 확인한다.
- **저장 방식:** 기기 내 저장을 기본안으로 검증한다. 공용 기기 노출, 기기 분실, 앱 삭제 시 기록 유실과 보호 방식을 함께 안내한다.
- **AI 제공자:** 한국어 코칭 품질, 응답 시간, 비용, 데이터 보관·학습 사용·삭제 조건을 비교한다.
- **동의 흐름:** 대상 연령과 운영 지역에 맞는 절차를 확인한다. 외부 AI 전송과 알림은 각각 선택하도록 한다.
- **운영 기준:** 기록 기본 90일 보관, 조용한 시간 22:00~08:00, 학습 리마인더 하루 최대 1회라는 기획안을 사용자 검증으로 점검한다.
- **시범 평가:** 표본과 기간, 자발적 참여·철회 방법, 성공 지표 목표를 실제 운영 전에 정한다. 시범 결과를 전체 고등학생에게 일반화하지 않는다.

## 5. MVP 검증 시나리오

1. 신규 학생이 계정 없이 목표와 가용 시간을 입력하고 첫 세션을 시작할 수 있다.
2. 휴식·회고를 포함한 계획 총시간이 가용 시간을 넘지 않으며, 초과 시 수정 경로가 보인다.
3. 일시정지·재개·앱 재진입·자정 경과 후 시간 기록과 통계가 일치한다.
4. 일부 완료와 미완료가 구분되고, 계획이 없는 날은 완료율을 계산하지 않는다.
5. AI 전송을 거절하거나 연결이 실패해도 기본 계획·타이머·통계를 사용할 수 있다.
6. AI 제안을 거절하면 기존 계획이 유지되고, 수락한 변경은 한 번만 반영된다.
7. 거절·중단·장기 미사용에 비난이나 보상 회수 없이 다시 시작할 수 있다.
8. 외부 알림 기본 꺼짐, 리마인더 하루 최대 1회, 조용한 시간 준수, 타이머 종료 알림 별도 선택이 작동한다.
9. 전체 기록 삭제와 보관 기간 만료 시 원본·통계·배지·개인화 요약이 함께 삭제되고, 늦게 도착한 AI 응답이 이를 복원하지 않는다.
10. 로그·잠금 화면 알림에 학습 원문이 노출되지 않고, 미동의 상태에서 외부 AI 전송이 발생하지 않는다.

## 6. 시범 운영에서 평가할 것

- 계획 확정 후 첫 세션 시작까지 걸린 시간과 입력 부담
- 최종 확정 계획 항목 완료율, 계획 수정 사유, 중단 후 같은 날 재시작 여부
- AI 제안 수락·수정·거절과 학생이 평가한 유용성
- 휴식이 충분했는지, 보상이나 알림이 부담·경쟁·과도한 공부를 유발했는지
- 기록 열람·삭제·동의 철회가 이해하기 쉽고 실제로 작동했는지

평가용 기록도 별도 수집 목적과 범위를 설명하고 필요한 최소 항목만 사용한다. 일반 사용 기록을 동의 없이 평가 자료로 전환하지 않는다. 출시 확대 여부는 사용 시간 증가만으로 판단하지 않는다.

## 7. 구현 계획 상세

화면 구성, 소스 디렉터리, 데이터 모델, 단계별 작업량과 검증 기준은 [프로젝트 구조와 개발 계획](05_프로젝트_구조와_개발_계획.md)을 따른다. 기본 흐름 → 통계·규칙 코칭·배지 → 외부 AI 순으로 구현한다.
