# FocusMate AI 집중 복귀 안내 설계

작성일: 2026-11-13 · 상태: 개발 전 설계 · 사용자 선택: 웹 우선

## 목적과 범위

집중·학습 타이머 실행 중 FocusMate 화면을 떠났다가 돌아온 학생이 공부를 이어 가도록 돕는다. 웹에서는 어떤 앱을 열었는지 확인하지 않으며 유튜브·인스타그램 실행을 차단한다고 표시하지 않는다. 다른 앱 위에 경고를 띄우거나 강제로 FocusMate로 돌아오게 하지 않는다.

기존 기획의 ‘앱 이탈을 집중 실패로 추정하지 않는다’ 원칙을 유지한다. 이번 기능은 타이머 기능에 포함하는 P0 항목이다. 운영체제 알림 권한이나 외부 AI 연결은 필요하지 않다.

## 동작 흐름

1. 설정에서 ‘집중 복귀 안내’를 켠다. 초기값은 켜짐으로 제안하되 타이머 시작 전에 기능과 끄는 방법을 안내한다.
2. 집중 종류의 세션이 running인 동안 문서가 hidden 상태가 되면 해당 세션 ID와 이탈 시각을 보관한다.
3. visible로 돌아오면 세션 상태와 종료 예정 시각을 먼저 다시 계산한다.
4. 같은 세션이 여전히 running이고 이탈이 5초 이상이면 복귀 안내를 한 번 표시한다. 5초는 짧은 화면 전환의 방해를 줄이기 위한 초기 제품값이다.
5. 휴식·일시정지·종료 상태에서는 표시하지 않는다. 숨겨진 동안 타이머가 끝났다면 종료·회고 화면을 우선한다.
6. 사용자가 안내를 닫으면 타이머 화면을 계속 사용한다. 반복 표시를 줄이기 위해 마지막 안내 후 60초 안의 새 이탈에는 안내하지 않는다. 이탈 한 건에는 안내가 한 번만 표시된다.

## 안내 문구와 선택

> 다시 집중해 볼까요?
>
> 잠시 화면을 벗어났어요. 준비됐다면 하던 공부를 이어 가세요.

- **공부 계속하기:** 안내를 닫는다. 실행 중인 타이머를 새로 시작하거나 시간을 초기화하지 않는다.
- **잠시 쉬기:** 현재 집중 세션을 일시정지한다. 기존 휴식 흐름으로 이동하며 집중·휴식 시간이 중복 집계되지 않게 한다.
- **세션 종료:** 기존 중단·회고 흐름으로 이동한다. 완료 여부는 학생이 선택한다.
- 안내를 닫거나 Escape를 누르면 공부 계속하기와 같은 결과가 된다.

안내창이 보이는 동안에도 타이머는 계속된다. ‘유튜브를 켰어요’, ‘집중 실패’처럼 관찰할 수 없는 내용을 문구나 통계에 넣지 않는다. 학습 자료 탐색이나 화면 잠금도 같은 숨김 신호를 만들 수 있다.

## 시간·저장 정책

화면 이탈만으로 타이머를 자동 일시정지하거나 실행 시간을 차감하지 않는다. 기록은 실제 주의 집중 측정값이 아니라 타이머 실행 시간이다. 앱이 비정상 종료된 경우에는 기존 복원·사용자 확인 정책을 우선한다.

세션 ID, pendingHiddenAt, lastPromptAt 정도의 최소 상태만 세션 복원 데이터에 넣는다. 방문 URL, 실행 앱 이름, 검색어를 수집하지 않는다. 별도의 장기 이탈 이력이나 실패 점수를 만들지 않는다. 세션 종료·설정 해제·전체 기록 삭제 시 대기 중인 안내 상태도 지운다. 새로고침을 새 이탈로 계산하지 않는다.

## 구현 위치

- `src/features/timer/useFocusReturnNotice.ts`: visibilitychange 구독과 정리, 숨김·복귀 판정.
- `src/features/timer/focusReturnPolicy.ts`: 세션 상태·시간·중복 안내 판정 함수.
- `src/features/timer/FocusReturnDialog.tsx`: 복귀 안내와 선택 버튼.
- `src/domain/`: 설정의 focusReturnNoticeEnabled와 복원 상태 타입.
- 기존 timer 저장·복원 어댑터: 안내 대기 상태의 저장과 삭제.

React 렌더링마다 이벤트 리스너를 중복 등록하지 않고 언마운트 시 정리한다. 주기적인 폴링 대신 Page Visibility API를 사용한다. 화면 blur만으로 앱 이동을 단정하지 않는다. 백그라운드 타이머 호출 빈도에 의존하지 않고 저장된 시각 차로 경과를 계산한다. 여러 탭에서는 활성 세션을 소유한 탭만 안내를 표시한다.

대화상자는 키보드로 사용할 수 있고 닫힌 뒤 타이머의 적절한 위치로 포커스를 복구한다. 설정을 끄면 현재 안내도 닫힌다. API 사용 불가 환경에서는 타이머 기본 기능을 유지한다.

## 완료 기준

- 실행 중 5초 이상 이탈 후 복귀하면 안내가 한 번 표시된다.
- 5초 미만 전환, 60초 안 재안내, 휴식·일시정지·종료 상태에서는 표시되지 않는다.
- 숨겨진 동안 종료 시각이 지났다면 회고가 우선하며 실행 시간을 초과 저장하지 않는다.
- 계속하기·닫기는 시간과 세션을 초기화하지 않는다.
- 쉬기·종료는 기존 상태 전환을 사용하고 기록을 중복 생성하지 않는다.
- 설정 해제·기록 삭제 후 오래된 이탈 정보로 안내를 띄우지 않는다.
- 새로고침·여러 탭·모바일 화면 잠금 이후에도 중복 안내와 기록 중복이 없다.
- 화면 이동을 특정 앱 사용이나 학습 실패로 표시하지 않는다.

개발 로드맵의 ‘집중·회고’ 단계에서 함께 구현한다. 현재는 설계 문서만 작성했으며 실행 가능한 기능 구현과 브라우저 검증은 아직 하지 않았다.

## 기술 근거

[MDN Page Visibility API](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API): 문서의 표시·숨김 상태와 visibilitychange 이벤트를 제공한다. 다른 탭 전환·최소화·화면 꺼짐 등이 숨김 신호가 될 수 있으며 백그라운드 타이머는 지연될 수 있다.
