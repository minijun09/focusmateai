# 03. AI 에이전트 설계

## 1. 역할과 결정권

AI 에이전트는 학생의 목표와 학습 기록을 바탕으로 다음 학습 행동을 제안한다. 계획 확정·변경의 결정권은 학생에게 있다. 초기 MVP에서는 무제한 자율 실행이나 다른 앱 제어를 허용하지 않는다.

전체 구조는 **입력 → 판단 → 행동 제안 → 학생 확인 → 실행 → 피드백**이다. 타이머, 기록 저장, 시간 합산, 알림 제한은 정해진 규칙으로 처리하고, AI는 계획과 코칭 제안의 개인화에 사용한다.

## 2. 입력

| 입력 | 필수 여부 | 사용 목적 | 최소화 방안 |
| --- | --- | --- | --- |
| 과목·짧은 할 일 | 계획 생성에 필수 | 학습 항목 구성 | 이름·학교 등 개인정보 입력을 요구하지 않음 |
| 오늘의 가용 시간 | 계획 생성에 필수 | 계획 총량 제한 | 상세 시간표·위치는 수집하지 않음 |
| 선호 집중·휴식 길이 | 선택 | 세션 구성 | 기본값 제공, 언제든 수정 |
| 마감일·우선순위 | 선택 | 순서 조정 | 필요한 항목에만 입력 |
| 세션 실행 시간·상태·완료 여부 | 기능 이용 시 생성 | 통계와 다음 제안 | 휴대전화 전체 사용 내역을 수집하지 않음 |
| 체감 난이도·중단 사유 | 선택 | 제안 길이와 분량 조정 | 선택형 입력 우선, 미응답 허용 |
| 제안 수락·수정·거절 | 제안 응답 시 생성 | 제안 적합성 확인 | 거절 이유와 유용성 평가는 선택 |
| 알림·AI 전송·개인화 설정 | 기본값 제공 | 허용된 처리 범위 결정 | 설정을 독립적으로 제어 |

자유 입력에는 개인정보를 적지 않도록 안내한다. 원문 전체를 기본 전송 대상으로 삼지 않고 과목, 시간, 최근 기록의 집계 등 필요한 항목만 구성한다. 자유 입력이 꼭 필요한 경우에도 외부 전송 전 학생이 내용을 확인하게 한다.

## 3. 판단

### 규칙 기반 검증

1. 가용 시간, 세션 길이, 일정 등 입력의 유효성을 확인한다.
2. 휴식과 회고를 포함한 계획 총시간이 가용 시간을 넘지 않는지 확인한다.
3. 기록이 없거나 불확실하면 기본 계획을 사용한다.
4. AI 전송 동의와 개인화 허용 여부를 확인한다. 동의 범위를 넘는 정보는 입력에 넣지 않는다.
5. 모델 출력이 허용된 항목·시간·행동 범위 안에 있는지 검사한다.

### 개인화 판단

- 최근의 확정 기록과 선택형 회고를 함께 참고한다.
- 반복된 중단이나 높은 체감 난이도가 있으면 더 짧은 세션·작은 분량·휴식 중 한 가지를 제안한다.
- 단일 중단만으로 집중력이 낮다거나 스마트폰에 중독됐다고 단정하지 않는다.
- 완료가 이어져도 자동으로 공부량을 늘리지 않는다. 학생이 원할 때만 조정안을 제안한다.
- 관찰된 사실과 제안을 구분한다. 근거가 적으면 “아직 기록이 적어 기본 길이를 제안해요”처럼 한계를 알린다.

초기 규칙 예시는 ‘최근 3회 중 2회에서 어려움을 선택한 경우 세션 분할 제안’이다. 이는 검증할 제품 가설이며 학생별 능력을 판정하는 기준이 아니다.

## 4. 행동과 승인 범위

| 행동 | 실행 방식 | 제한 |
| --- | --- | --- |
| 계획 초안 만들기 | AI 또는 기본 규칙이 제안 | 저장된 확정 계획을 자동 대체하지 않음 |
| 계획 변경 | 학생이 수락·수정 후 반영 | 거절 시 기존 계획 유지, 중복 적용 방지 |
| 타이머 시작·중단 | 학생의 직접 조작으로 실행 | AI가 임의로 세션을 시작하지 않음 |
| 학습 결과 기록 | 세션 시간 저장, 완료 여부는 학생 확인 | 불확실한 종료 구간은 확인 전 확정하지 않음 |
| 코칭 표시 | 회고 화면 또는 요청 시 제공 | 짧은 근거와 한 가지 다음 행동 중심 |
| 배지·통계 갱신 | 확정 기록에 따라 규칙으로 처리 | AI가 점수·실행 시간을 만들어 내지 않음 |
| 외부 알림 | 설정과 시간·빈도 규칙에 따라 처리 | 모델이 알림 횟수·조용한 시간을 우회할 수 없음 |

AI 응답은 제안 항목, 제안 이유, 참조한 기록 범위로 구성한다. 실제 변경 직전 가용 시간과 현재 계획을 다시 확인하고, 상태가 달라졌으면 새로 검토하게 한다.

## 5. 피드백

- 세션 후 완료·일부 완료·미완료를 확인하고, 난이도·중단 사유는 건너뛸 수 있게 한다.
- 제안에 대한 수락·수정·거절과 선택적 유용성 평가를 다음 제안에 참고한다.
- 학생이 바꾼 집중 길이나 분량을 우선하며, 거절한 제안을 반복해서 강요하지 않는다.
- 개인화는 저장된 최근 기록을 참고하는 방식으로 시작한다. 학생 기록으로 모델을 자동 학습시키는 기능은 MVP에 포함하지 않는다.
- 개인화를 끄면 과거 기록을 코칭 입력에서 제외하고 현재 요청과 기본 규칙만 사용한다. 통계용 기록 보관과 전체 삭제는 별도로 선택할 수 있다.
- 90일 보관 기간이 지난 기록은 개인화와 통계에서 제외하고 삭제한다.

## 6. 예시 흐름

| 단계 | 예시 |
| --- | --- |
| 입력 | 가용 시간 60분, 수학·영어 할 일, 최근 수학 3회 중 2회 ‘어려움’ 선택 |
| 판단 | 수학을 짧게 나누는 제안이 도움이 될 가능성 확인, 총시간 검증 |
| 제안 | 수학 15분 → 휴식 5분 → 수학 10분 → 휴식 5분 → 영어 20분 → 회고 5분 |
| 학생 확인 | 학생이 영어를 15분으로 수정하고 확정, 총 55분으로 5분 여유 확보 |
| 실행 | 학생이 타이머 시작, 실제 실행 시간과 완료 여부 기록 |
| 피드백 | 분량 적절성 평가를 선택적으로 받고 다음 계획에서 참고 |

수학 분할의 이유는 학생이 직접 남긴 난이도 기록이며, 스마트폰 사용이나 집중력 저하를 추정한 결과가 아니다.

## 7. 오류와 예외 처리

- **외부 AI 미동의·연결 실패:** 기본 규칙으로 계획과 안내를 제공하고 실패한 요청을 자동 반복하지 않는다.
- **형식 오류·시간 초과·부적절한 조언:** 제안을 적용하지 않고 기본안으로 돌아간다. 학생 기록과 타이머 상태는 유지한다.
- **기록 부족·누락:** 추측으로 채우지 않고 현재 입력과 기본값을 사용한다.
- **앱 종료·중복 요청:** 마지막 확정 상태를 복원하고 같은 결과나 계획 변경을 중복 저장하지 않는다.
- **입력 안의 실행 지시:** 학생이 적은 할 일은 데이터로 취급한다. 그 안의 문장이 승인·데이터 접근·알림 규칙을 바꾸지 못하게 한다.

## 8. 데이터 보호 경계

- 기본안은 계정 없는 기기 내 저장이다. 외부 AI를 선택한 경우에만 동의한 최소 요약을 전송한다.
- 전송 구간 보호, 저장 데이터 보호, 민감한 원문을 남기지 않는 오류 기록을 개발 요구사항으로 둔다. 구체적인 구현은 플랫폼 선정 후 결정한다.
- 외부 AI 제공자의 요청 보관·모델 학습 사용·삭제 조건을 확인하기 전에는 실제 학생 기록을 연결하지 않는다.
- 기록 삭제는 원본, 파생 통계, 보상 이력, 개인화용 요약을 함께 대상으로 한다. 진행 중인 AI 요청을 취소하거나 응답을 버려 삭제한 기록이 복원되지 않게 한다.
- 동의 철회 후 신규 AI 전송을 중단한다. 이미 전송된 정보의 처리·삭제 범위는 제공자 조건에 맞춰 사전에 설명한다.
- MVP에서는 서버 기록 동기화와 보호자·교사 공유를 제외한다. 향후 추가 시 권한, 보관 기간, 백업 삭제 범위를 별도 설계한다.
